### What the 353 integration checks actually prove

Anonymous access denied (401) on every route; cross-branch and cross-restaurant
isolation; tampered client prices ignored; concurrent idempotent order creation
produces exactly one order and one stock deduction; concurrent payments cannot
overpay; refunds reject `-1 / 0 / NaN / 0.001 / 1e2`, cannot over-refund
concurrently, and restore stock from the *original* deduction (not the changed
recipe); owner-only order deletion returns stock and rolls shift totals back so
the drawer still reconciles; the read-only accountant role reads history/drawer
but is refused (403) on sell/pay/refund/edit/delete/shift-open; cost prices are
redacted for cashiers; session revocation on password/PIN change; login/PIN/refund
throttling; offline queue branch isolation and store-verification; accounting
suite proves split-tender, MoMo-vs-cash drawer, old-sale refund and close/refund
race reconciliation.

## 4. Findings & recommendations

### P1 — fix before / at next production deploy

**F1. `npm run build` fails without `DATABASE_URL`.**
`src/db/index.ts:6` throws at module import, so Next's page-data collection
dies with `Failed to collect configuration for /api/audit-logs`. The security
suite only passes because it sets the env before building. Any CI job, preview
or colleague building without a DB env hits this.
*Fix:* lazy pool creation (create on first use, not import), or guard the throw
to request/runtime paths. Add a plain `npm run build` (no env) step to CI.

**F2. No HTTP security headers.**
Verified live: no CSP/HSTS/nosniff/frame protection, and `X-Powered-By` is on.
The app handles money and session cookies; clickjacking and MIME-sniffing
should not rely on the reverse proxy alone.
*Fix:* `headers()` in `next.config.ts` (CSP allowing self + inline display-size
script nonce/hash, `frame-ancestors 'none'`, HSTS in prod,
`poweredByHeader: false`). Test the till/KDS screens after CSP lands.

**F3. Audit-trail erasure remains the top accounting/compliance risk**
(owner's documented decision, re-confirmed here, not a bug). Owner-only order
deletion wipes the order, payments, refunds and linked audit rows; re-pricing
keeps no before/after. After deletion the system cannot prove the order
existed. The pilot suite even asserts "no audit trace of the erased order".
*Recommendation:* keep erasure if the owner insists, but add a minimal
tombstone (order number, totals, actor, timestamp, reason) in a table even the
owner cannot delete from the UI — this preserves drawer reconciliation evidence
for GRA/accountant queries at near-zero UX cost. Revisit with the accountant.

**F4. No query indexes for the hot paths.**
`schema.ts` defines zero secondary indexes; migrations add only unique/identity
indexes. Reports and order history filter/sort by `(branch_id, created_at)`,
audit logs and payments join by order/shift. Fine at pilot scale (~2k orders),
a seq-scan liability at multi-year scale.
*Fix:* add `(branch_id, created_at DESC)` on `orders`, `payments`, `refunds`,
`audit_logs`, `stock_movements`; verify with `EXPLAIN ANALYZE` on a restored
backup. Cheap now, painful later.

### P2 — fix in the next hardening pass

**F5. Workflow audit debt (27 warnings + 56 notes, 0 failures).**
27 fetch sites parse JSON without checking `res.ok` (list loaders can show an
empty list instead of an error on a proxy 502), and 56 blocking `alert()` calls
remain in manager screens (till path already uses in-app notices).
*Fix:* one shared `apiFetch` helper that throws on `!ok` with the server's
message; route the 27 sites through it; migrate `alert()` screen-by-screen to
the existing `Toaster`. Then promote both audit rules from warn to fail.

**F6. Dev-only dependency vulnerabilities & staleness.**
`npm audit` = 9 (braces/micromatch via `eslint-config-next`; esbuild ≤0.24.2 via
`drizzle-kit`'s `@esbuild-kit` chain — dev-server request exposure). Production
tree is clean (0). `eslint@9.39.4` is EOL-warned; 15 packages are behind latest.
*Fix:* never `npm audit fix --force` (it proposes breaking downgrades);
upgrade `eslint`/`eslint-config-next` and `drizzle-kit` on their normal cadence
and re-run the security suite. Track in `docs/DEPENDENCY_REVIEW.md`.

**F7. Type-safety erosion in the client (123 `any`).**
`strict: true` is undermined exactly where API shapes are consumed
(`currentUser: any`, `any[]` lists). Server code is well-typed; drift will
surface as runtime breakage, not compile errors.
*Fix:* introduce shared DTO types for API responses (derive from Drizzle
`$inferSelect` where possible), type `page.tsx` state first, then the three
largest components. Consider an ESLint `no-explicit-any` warn ratchet.

**F8. God components & no UI test layer.**
`PosTerminal` (2,031 lines) plus five 600–1,000-line screens, all state in
`page.tsx`, no error boundary (`error.tsx` absent — a render crash is a white
screen on a till mid-service), and no browser tests in CI.
*Fix (in order):* add `error.tsx` + a component error boundary with a
"reload till" recovery; extract PosTerminal's cart/pricing/payment hooks
(behavior-preserving, the integration suite is the safety net); add 3–5
Playwright smoke tests (login → sale → pay → refund) to CI.

**F9. Observability is `console.error` only.**
29 call sites, no request IDs, structured logs, metrics or alerting. F1-class
and schema-drift failures are only visible if someone reads server logs.
*Fix:* request-ID + structured JSON logging at the `secureRoute` boundary
(the one place every request passes), keep 5xx payloads generic to clients as
today, and document log shipping in the VPS runbook.

### P3 — hygiene

- **F10.** `/favicon.ico` 404 (verified live). Point `layout.tsx` at
  `/logo.svg` or add the .ico. One line.
- **F11.** Service-worker `VERSION = "lushview-pos-v1"` is a hand-bumped
  constant; stale-shell risk if forgotten. Derive from `APP_BUILD_COMMIT`
  (already baked in by `next.config.ts`).
- **F12.** Root HTML `s-maxage=31536000`: make the caching decision explicit
  for `/` (short/no-store for HTML, immutable only for hashed chunks) so a
  redeploy can never strand a terminal on an old shell.
- **F13.** Offline attribution quirk (documented): a queued order is filed
  under whoever syncs it. Add the uploader-vs-author disclosure to the sync
  notice as the prior audit recommended.
- **F14.** `package.json` name is still `nextjs-postgresql-template`; rename
  to the product name for release artifacts and logs.
- **F15.** Migration truth is triple-maintained (`schema.ts`, SQL files,
  `schema-guard.ts` lists) — currently guarded by an audit rule; long-term,
  generate the guard list from migrations in CI rather than by hand.

## 5. What is genuinely strong (keep doing this)

1. **Request boundary design** — one `secureRoute` wrapper, transactional
   rollback on any ≥400, RLS-bypass refusal, tamper canary, fail-closed auth.
2. **Money integrity** — integer minor units, server-side pricing, idempotency
   with request fingerprints, row locks, DB check constraints; the accounting
   suite proves drawer reconciliation under races.
3. **Test realism** — disposable PostgreSQL, restricted runtime role, actual
   migrations, production build, multi-branch/multi-restaurant fixtures.
4. **Honest documentation** — open items are written down with severities
   (`docs/SYSTEM_AUDIT.md`), and static audits encode past bug classes
   (permission disagreement, swallowed failures) as CI failures.

**Known consequence to note:** tombstones retain the deleted order's number,
